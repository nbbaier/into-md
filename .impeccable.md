## Design Context

### Users
Developers building LLM-powered applications and general developers who need clean web-to-markdown conversion. They value tools that work reliably, have clear documentation, and don't waste their time. Context: typically discovered via npm/GitHub, evaluated quickly, used from the terminal.

### Brand Personality
**Precise, minimal, sharp.** into-md is a no-nonsense developer tool. It does one thing well and communicates that clearly. The interface should feel like the tool itself: clean input, clean output, nothing extra.

### Aesthetic Direction
Refine the current direction: light, clean, subtle box shadows, minimal palette. Let whitespace and typography carry the design. No decoration for decoration's sake. The site should feel like well-typeset documentation — confident, readable, and quiet.

### Design Principles
1. **Clarity over cleverness** — Every element should communicate, not decorate
2. **Typographic confidence** — Strong hierarchy through weight, size, and spacing rather than color or ornament
3. **Developer-native** — Respect the audience's aesthetic sensibility; avoid marketing fluff
4. **Quiet precision** — Small details done right (spacing, alignment, measure) over flashy effects
5. **Light and airy** — Generous whitespace, soft background, minimal visual weight
